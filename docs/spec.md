# 輸入方案規格 — 阿特雙拼輸入法

本檔為輸入行為的**規格權威**；`core\` 的實作與測試以此為準。
鍵位源自 Rime 方案 `mspy_zhuyin.schema.yaml`（speller/algebra）的定案，移植時以本檔表格為可讀形式。

## 1. 音節結構

每個音節 = **2 鍵**（聲母鍵 + 韻母鍵）+ **選擇性聲調數字**（1-5）。
音節邊界是決定性的：第 2 鍵落下即音節完成；其後若是數字則為聲調，否則開始下一音節。

**單鍵音節（2026-08-08 新增，2026-08-09 擴及全部聲母）**：省略韻母鍵，
按聲調鍵或空白鍵即直接成字，該音節只花 2 鍵（含聲調）。**26 個字母鍵全部都是單鍵音節。**

| 鍵 | 注音 | 例 |
|---|---|---|
| `z` `c` `s` `r` | ㄗ ㄘ ㄙ ㄖ | 字＝`z4`、此＝`c3`、四＝`s4`、日＝`r4` |
| `v` `i` `u` | ㄓ ㄔ ㄕ | 知＝`v`＋空白、吃＝`i`＋空白、是＝`u4` |
| `y` `w` | ㄧ ㄨ | 一＝`y`＋空白、五＝`w3` |
| `a` `e` `o` | ㄚ ㄜ ㄛ | 啊＝`a`＋空白、餓＝`e4` |
| `b` `p` `m` `f` | ㄅㄛ ㄆㄛ ㄇㄛ ㄈㄛ | 播＝`b`＋空白、頗＝`p3`、麼＝`m5`、佛＝`f2` |
| `d` `t` `n` `l` `g` `k` `h` | ㄉㄜ ㄊㄜ ㄋㄜ ㄌㄜ ㄍㄜ ㄎㄜ ㄏㄜ | 的＝`d`＋空白、特＝`t4`、呢＝`n`＋空白、了＝`l`＋空白、個＝`g`＋空白、科＝`k`＋空白、賀＝`h4` |
| `j` `q` `x` | ㄐㄧ ㄑㄧ ㄒㄧ | 機＝`j`＋空白、七＝`q`＋空白、西＝`x`＋空白 |

前四列是「注音本身就是音節」；後三列是**注音的呼名**——
ㄅㄆㄇㄈ 呼名帶 ㄛ（**沒有 ㄅㄜ 這個音節**，詞庫 0 筆）、ㄉㄊㄋㄌㄍㄎㄏ 帶 ㄜ、ㄐㄑㄒ 帶 ㄧ。
實作上「省略韻母鍵」＝「幫你按下那個預設韻母鍵」，所以 `d` 與 `de` 是同一個讀音 ㄉㄜ，
單鍵形式不可能表示兩鍵形式表示不了的東西（`DecodeSingleKey` 直接轉呼 `DecodeKeyPair`，
有測試綁住這個等價關係）。

- `f`＋空白沒有字：ㄈㄛ 只有二聲（佛），無一聲／輕聲條目，會照 §6 規則定案成注音符號 ㄈ；佛＝`f2`。
- `n`＋空白從「定案成注音符號 ㄋ」變成「呢」（ㄋㄜ 有一聲條目）。要打純注音 ㄋ 就**直接按 Enter**（2026-08-17：Enter 原樣送出畫面上的注音，見〈注音符號輸入〉）。

- 這些鍵**仍然可以接韻母鍵**（`u`＋`l`＝ㄕㄞ）：只有聲調鍵與空白鍵會把單鍵當音節收掉並轉成字（2026-08-17 起 **Enter 不再轉換**，它把畫面上的注音原樣送出）。
- **單鍵音節與下一個字之間一律要隔開**：接空白鍵或聲調鍵，沒有例外。拼不出音節的鍵一律吃掉無作用（`v`+`q`＝維持 ㄓ）。
  - **決策記錄（2026-08-08 實作後同日撤銷，勿再實作）**：曾做過「下一鍵與單鍵拼不出任何存在音節時自動分割」——知情＝`vq;` 三鍵、資訊＝`zxp`，分割後前音節維持未定案（`ㄓㄑ` → `知ㄑㄧㄥ`）不閃錯字，實作乾淨且測試全綠。撤銷原因：**只在「拼不出來」時才成立**，而 `v`+`u`＝ㄓㄨ 是有效音節，所以知識永遠得隔開——同一組肌肉記憶在知情能用、在知識會失控（使用者實測回報）。規則改為「單鍵音節一律用空白/聲調收尾」，一致優先於省一鍵。
  - 兩個字都是單鍵音節、且第一個字沒聲調的詞共 62 個需要隔開（一直、支持、知識、之一、醫師、師資、獅子、屋子、姿勢、失誤…），詞庫全掃結果見 2026-08-08 狀態記錄。
- `y` 維持 ㄧ 而非 ㄩ（2026-08-08 拍板）：詞庫統計 ㄧ 系音節總頻率是 ㄩ 系的 4.1 倍
  （單音節 ㄧ 0.0159 vs ㄩ 0.0039），且詞格一個節點只能有一個讀音，單鍵無法同時是兩者。
  ㄩ 維持 `yu`／`yy` 兩鍵＋聲調；ㄦ 維持 `er`＋聲調。

## 2. 聲母鍵

| 聲母 | 鍵 | 備註 |
|---|---|---|
| b p m f d t n l g k h j q x r z c s | 同字母 | |
| zh | `v` | |
| ch | `i` | |
| sh | `u` | |
| y w | 同字母 | 拼音 yi/wu/yu 系列視為 y/w 聲母 |
| （零聲母） | `o` | 見 §4 |

### 3.0 一鍵兩義的韻母鍵：由詞庫決定

`o`(ㄛ/ㄨㄛ)、`w`(ㄧㄚ/ㄨㄚ)、`y`(ㄩ/ㄨㄞ)、`d`(ㄧㄤ/ㄨㄤ)、`v`(ㄨㄟ/ㄩㄝ)、`r`(ㄦ/ㄨㄢ)、`s`(ㄨㄥ/ㄩㄥ)
一鍵對到兩個韻母。`DecodeKeyPair` 只做**結構**過濾（回傳所有可能），
**哪一個才是真的音節由詞庫決定**——`SyllableInput` 的 validator（`Composer` 注入，查該注音的任一聲調是否存在）
同時決定 (a) 畫面顯示哪一個、(b) 這組按鍵到底成不成立。

- 2026-08-08 修正：先前只有「轉換」查詞庫、「顯示」直接取第一個候選，於是
  `hy`（懷）顯示成不存在的 **ㄏㄩ**。全鍵位掃描共 11 組同類錯誤：
  `gd gw gy hd hw hy kd kw ky`（ㄍㄎㄏ 不接 ㄧ 介音與 ㄩ）與 `lv nv`（ㄌㄋ 不接 ㄨㄟ，應為 ㄌㄩㄝ/ㄋㄩㄝ）。
- 另有 102 組**兩個候選都不存在**的鍵組（`bb`＝ㄅㄡ、`df`＝ㄉㄣ、`kz`＝ㄎㄟ、`ra`＝ㄖㄚ…），
  以前會顯示假注音，現在一律**不接受該鍵**（等同結構不合法：組字中吃掉、或觸發 §1 的單鍵分割）。

## 4. 零聲母音節

- 通則：`o` + 韻母鍵。例：安=`oj`、昂=`oh`、歐=`ob`、啊=`oa`、餓=`oe`。
- a/e 開頭音節另可用**首字母雙打形**：啊=`aa`、愛=`al`、安=`aj`、恩=`ef`、餓=`ee`、二=`er`。
- 兩種拼法並存（與 Rime 版一致）。

## 5. 聲調語意（嚴格模式，2026-07-26 拍板，勿再反覆）

| 輸入 | 候選範圍 |
|---|---|
| 不打數字 | **只出一聲＋輕聲**字詞（`de` → 得(ㄉㄜ)、的(ㄉㄜ˙)；不出 ㄉㄜˊ） |
| `1` | **嚴格只出一聲**（`de1` 不出「的」） |
| `2` `3` `4` | 精確該聲調 |
| `5` | 只出輕聲 |

- 「我」必須打 `wo3`；`wo` 只出「窝」等一聲字。
- **聲調鍵左右手鏡像（2026-08-04 新增）**：右手以 5／6 之間為軸取得同一組聲調——

  | 聲調 | 左手 | 右手 |
  |---|---|---|
  | 一聲 | `1` | `0` |
  | 二聲 | `2` | `9` |
  | 三聲 | `3` | `8` |
  | 四聲 | `4` | `7` |
  | 輕聲 | `5` | （無，2026-08-17 起 `6` 是 Backspace） |

  一到四聲兩組完全等價（`ge1` ＝ `ge0` ＝ ㄍㄜˉ → 歌）。**輕聲只剩左手的 `5`**：
  `6` 在 2026-08-17 整個讓給 Backspace（見 §6〈數字鍵的兩種身分〉），
  這是使用者知情下推翻 2026-08-14「`5`/`6` 不能挪用」的決定。
  **實務上一聲與輕聲幾乎不必打**：不打數字本來就涵蓋這兩個，明打只用於「排除另一個」
  （`ge1` 排掉輕聲的「個」、`ge5` 排掉一聲的「歌」）。看打練習因此只出 2/3/4（與鏡像的 9/8/7）。鏡像鍵與 `8` 開選單／`9`/`0` 移游標的衝突，
  以「未定案窗口」切開：見 §6〈數字鍵的兩種身分〉。
- **聲調鍵按下即定案成字（2026-08-08 復原，取消 2026-08-04 的「打了調仍維持注音」）**：`hk3` 直接顯示「好」，
  數字鍵隨即回到控制鍵身分。打錯調＝Backspace 刪掉整個音節重打（不再有退調）。
- **該聲調查無條目時＝按鍵吃掉、聲調窗口不關**（`vs2`：詞庫無 ㄓㄨㄥˊ，維持 ㄓㄨㄥ，可再按 `3`）。
- 詞庫鍵格式：一聲不標記、2/3/4 聲尾綴 `ˊˇˋ`、輕聲尾綴 `˙`。
  無數字查詢＝「無標記 ∪ `˙` 尾綴」合併；明打 `1` 只查無標記鍵（實作經內部哨兵記號區分）。
  組字畫面上**明打的一聲標 `ˉ`（U+02C9）**，與「還沒給聲調」的裸注音區分；輕聲畫面上一律**尾綴** `˙`
  （2026-08-04 拍板：與 2/3/4 對齊，不採注音書寫的前綴慣例）。
- 決策記錄（2026-07-27 拍板不採用）：曾評估「含輕聲的詞加去聲調 alias 鍵」讓 `erzi` 免打聲調出「兒子」；確認為使用者操作誤解（打實調 `er2zi` 即可），嚴格語意維持原樣。

## 6. 模態互動（微軟注音式）

### Composing（組字中）
- 行內顯示：已轉換的整句最佳路徑 + 未完成音節的注音尾（如 `ㄕ`）。
- **首鍵一律顯示注音、不顯示英文字母**（2026-07-27 對齊）：有聲母符號的鍵照聲母（b→ㄅ、u→ㄕ…）；無聲母符號的鍵顯示代表性符號——`y`→ㄧ、`w`→ㄨ、`a`→ㄚ、`e`→ㄜ、`o`→ㄛ（第二鍵落下後修正為實際音節）。
- **單色顯示（2026-07-29 定案，取代雙色）**：整段組字＝應用程式預設文字色＋**虛線底線直到 commit**。決策記錄：原「藍色＝聲調未定/殘鍵」的換色只有完整 TSF app（記事本/Word）會畫、LINE/Sublime 等一律不顯示，應用面太窄故整個移除；黑/藍分段語意仍存在於內部 segments（游標與錨點計算沿用），僅視覺取消。選字錨點淡藍反白**保留**。
  - 顯示屬性實作註記（2026-07-28）：定調段的 attr-info 用 `TF_ATTR_INPUT`——Chromium 系 app（LINE、Chrome）會把 `TF_ATTR_TARGET_CONVERTED` 畫成黑色選取反白並忽略顏色；選字錨點淡藍反白維持 `TF_ATTR_TARGET_CONVERTED`（在 Chromium 呈反白屬可接受的強調）。
- 每完成一個音節即重跑整句轉換（walk），前文可能隨上下文自動修正。
- **未定案窗口（2026-08-08 收回到 2026-08-02 版：只涵蓋「還沒給聲調」）**：音節第 2 鍵落下後**不顯示轉換後的字**，維持注音（`hk` → ㄏㄠ，不是「蒿」）。該音節其實已進詞格（整句轉換照跑、前文照樣自動修正），只是顯示層蓋成注音。
  - **定案**（注音轉成文字）的觸發：**聲調鍵、空白鍵、標點符號、下一音節首鍵**。（`` ` `` 曾經也是，2026-08-17 移除。）
  - 同時只有**最新**一個音節處於未定案。
- **組字中數字全為控制鍵，絕不字面輸出**（2026-07-27 大改版拍板）。
  **數字鍵的兩種身分（2026-08-04 拍板）**——由「有沒有未定案的音節」決定，畫面上看得出來（有注音＝未定案）：

  | 狀態 | `0`-`9` |
  |---|---|
  | 未定案（畫面上是注音 ㄏㄠ） | **`6` 是 Backspace**，其餘全部是聲調鍵（含鏡像，見 §5） |
  | 已定案（畫面上是字 好） | `5` Delete、`6` Backspace、`8` 開選單、`9`/`0` 移游標，其餘吃掉 |

  - **`5`/`6` 在組字串內刪字（2026-08-14 新增）**：與閒置時同一個位置、同一件事，
    手不用離開主鍵區。`5` 走 `Composer::feedDelete()`（`deleteReadingAfterCursor`），
    `6` 走 `feedBackspace()`。
  - **`6` 在未定案狀態也是 Backspace（2026-08-17，推翻 2026-08-14）**：原本規定
    「畫面上還是注音時每個數字都是聲調鍵，而 `5` 與其鏡像 `6` 是**輕聲僅有的兩個鍵**，
    不能挪用」。使用者裁示改掉：`6` 從此在**每一個狀態**都是 Backspace，
    輕聲因此**只剩左手的 `5`**（不打數字本來就涵蓋一聲＋輕聲，明打只在要排除另一個時才用）。
    代價是聲調鏡像少一個鍵，換來的是刪除不必把手移開主鍵區、也不必先判斷畫面是字還是注音。

  - 規則單一——「畫面上還是注音 → 數字是聲調鍵」。聲調鍵本身就會定案，所以打完調馬上可以按 `8` 選字（`ni3hk3` → `8`）；只有「不給聲調」的音節要先按空白定案。
  - `-`/`=` 曾經是「游標跳組字串頭／尾」，**2026-08-14 取消**：它們現在什麼都不做（連同閒置時的 Home/End 一起收回，見〈閒置編輯層〉）。組字串內的游標一律用 `9`/`0` 一格一格走。
  - 打錯聲調＝**Backspace 刪掉整個音節重打**（2026-08-08 拍板：聲調鍵一按即定案，沒有可退的調；已評估「保留退調一步」的替代案，使用者選擇規則單純優先）。
- **無組字時按數字：整排變成編輯鍵（2026-08-14，取代原本的「吃掉無作用」）**，見〈閒置編輯層〉。要輸入數字＝用 NumPad，或先 Shift 切英文（英文模式下只要組字串非空，數字就是字面數字）。
- **九宮格（NumPad）豁免（2026-07-28 新增）**：禁用只針對字母上方的數字排。NumPad 數字與運算符／小數點（`* + - . /`）閒置時直接放行字面輸入；**組字中按 NumPad＝先整段自動上屏、再輸出該字元**（比照標點 commit 慣例）。NumLock 關閉時 NumPad 送方向鍵等，維持既有行為。
- **游標錨點反白**：游標右邊的那個字以淡藍底色強調，表示按 `8` 會從該字開始選字；游標在最右端時無反白，此時按 `8` 選最後一個字。
- **方向鍵（←/→/↑/↓/PgUp/PgDn）在組字中一律吃掉無作用**（2026-07-27 移除選字功能；避免游標逃出組字範圍）。
- **空白鍵＝定案，永不 commit（2026-08-02 立、2026-08-16 拿掉最後一條 commit 路徑）**：
  - 有待定注音／音節時：**只定案不上屏**——完整音節以「一聲/輕聲」預設讀音轉成字（ㄏㄠ → 蒿）；沒有無聲調讀音的注音（`f`＝ㄈㄛ、或詞庫查無無聲調條目的 ㄋㄧㄠ）則把注音本身定案成固定符號融入組字串。
  - **沒有東西可定案時**（最新音節已定案，或剛打完標點）：**打出一個半形空白**，以固定符號（literal 讀音）融入組字串，**不 commit**（2026-08-16，取代原本的「整段 commit，與 Enter 同」）。它就是一般的組字串內容：游標走得過、Backspace 刪得掉、和整段一起上屏。
  - 例外：組字串裡實際上什麼都沒有時回到閒置，**不會**開一段只有空白的組字串。
  - 閒置時：一般半形空白（放行給應用程式）。
  - 理由（2026-08-16 使用者裁示）：上屏應該只有 Enter 一個入口。標點與英文早就不 commit 了，空白是最後一個會突然把整段送出去的可見字元，而它同時又是最常按到的鍵。
- **標點符號＝定案並融入組字串，不 commit（2026-08-04 改版，取代「連同前文一起上屏」）**：
  - 打標點時先把未定案音節定案成字（`zv7` ㄗㄨㄟˋ → 按 `,` → 「最，」），標點本身以固定符號（literal 讀音）加進組字串，**整段維持虛線底線、未上屏**。
  - 標點之後**照樣可以選字**：游標走得過標點，`8` 對標點兩側的字開選單；Backspace 逐符號刪。
  - **閒置時打標點＝開一段新的未 commit 組字串**（而非直接上屏）。
  - **不設任何自動上屏界線（2026-08-04 拍板）**：組字串可以無限長，自 2026-08-16 起只剩 **Enter／失焦／組字中按 NumPad**（NumPad 會先整段上屏再輸出該字元）會上屏（Esc 則是整段丟棄）。已評估「句末標點仍上屏」「字數上限」兩種安全網，使用者選擇完全手動控制。
  - 表：`,` `.` `?` `!` `:` `\` `/` `[` `]` `{` `}` `(` `)` `<` `>` `^` `_` `~` → 全形「，。？！：、、「」『』（）《》……——～」；`"`/`'` 開閉交替；`;` 單獨時為「；」、組字中仍為 ing 韻母鍵。
  - **`/`＝、（2026-08-14 新增）**：對齊小狼毫（Rime `punctuator/half_shape` 把 `\` 與 `/` 都對到 、），而 `/` 比 `\` 近得多。兩個鍵都留著。
  - **`-` `=` `+` ＝半形，直接打出（2026-08-16 解禁）**：Rime `punctuator/half_shape` 在同一套微軟雙拼鍵位下就是把這三個鍵原樣送出（`-`→`-`、`=`→`=`、`+`→`+`），使用者要的就是與小狼毫一致的手感；中英混排時它們也用得夠頻繁，為了一個連接號切一趟英文並不划算。行為與其他標點完全相同：先定案未定案音節、以固定符號融入組字串、不 commit。`_`→「——」本來就是 Rime 的對映，不變。
  - **`` ` ``＝半形 `` ` ``（2026-08-17 解禁）**：注音功能鍵移除後，這顆鍵與 `-` `=` `+` 同一類，行為也相同（定案未定案音節、融入組字串、不 commit）。Shift 位的 `~` **維持全形 ～**。
  - **其餘沒有對映的符號鍵一律吃掉，閒置時也不輸出（2026-08-14）**：`@ # $ % & * |`。中文模式不讓這些半形字元漏進文件——與「數字排禁用」同一個取捨。要打就 Shift 切英文。
  - 決策記錄（2026-08-14）：曾比對 Rime `symbols.yaml` 的 `half_shape` 逐鍵對齊，結論是**只採用 `/`→、**。`|`→· 與 `$`→￥ 雖然也是全形，但使用者裁示「只加 `/`，其他都不動」；`~` 維持全形 ～（Rime 給半形 `~`）。Rime 那些鍵大多是**候選清單**（`[` 可選 「【〔［），本輸入法的候選窗只服務中文字，一律取第一個——標點候選清單已明確決定不做。
- **Backspace：一次一個鍵，只要畫面上還是注音**（2026-08-17 修正）：`bc` 顯示 ㄅㄧㄠ，
  按一次剩 ㄅ，再按一次才空。以前只有「拼不出字的音節」（`nc`＝ㄋㄧㄠ）是這樣，
  而能轉成字的音節（ㄅㄧㄠ 已經以一聲進了詞格）會被整個刪掉——同一個畫面兩種行為。
  實作：`Unsettled` 記下拼出它的原始按鍵（`keys`），Backspace 先把詞格節點拿掉，
  再把「少最後一鍵」的部分重新餵回 `pending_`。已定案的字仍是逐字／逐符號刪。
  **Tab 不再是 Backspace**（2026-08-14 取消，見〈閒置編輯層〉）。
- **Enter：所見即所得，原樣上屏**（2026-08-17 改版，取代「丟棄未定案的殘鍵」）：
  送出的就是 `composedText()`＝畫面上的那一串。還顯示成注音的部分**以注音送出**，
  既不會被丟掉，也不會在送出的瞬間被換成字：`nc`→ㄋㄧㄠ（以前是**什麼都沒有**）、
  `k`→ㄎ（以前是「科」）、`ni3hk`→你ㄏㄠ（以前是「你蒿」）。
  要字就先按空白鍵或聲調鍵——那兩個鍵才是「轉成字」的指令，Enter 只負責送出。
- Esc：清空組字（候選選單開啟時一併取消）。**一按全清，不分段**（2026-08-04 拍板：標點不再上屏後組字串可能很長，仍評估後維持原行為，不加「先取消未定案再清空」的兩段式）。

### Selecting（候選選單開啟）
- 進入：**僅**數字 `8`（於游標錨點的詞段開窗；游標在最右端時選最後一個字）。
- 每頁最多 **6** 個候選；數字 `1`-`6` 選字（選定即釘選該詞段，關窗回 Composing）；按了本頁沒有的編號＝無作用。
- **選字不動到其他字（2026-08-09 新增）**：套用候選後，**所選跨距以外**每一個被重走改掉的位置都會被釘回原本的字（單字覆寫，改完再走一次，直到穩定）。
  起因：詞格的 `overrideCandidate` 會 reset **所有與所選跨距重疊的節點**，所以在「不鏽鋼[悲]」選兩字候選「鋼杯」會拆掉 `不鏽鋼` 這個三字節點，剩下的 `不鏽` 重新斷詞就變成「不秀」。
  現在改字只會動到你選的那幾個字；只有既有詞裡拆不出單讀音節點的字（釘不回去）例外。
- **選定後游標跳到該詞段之後（2026-08-02 新增）**：錨點自動變成下一個字，可以連續按 `8` 一路往右改完整句，不必再用 `9`/`0` 移游標；選的是多字詞就整段跳過（選 2 字詞＝游標前進 2）。游標已在最右端時留在原地（`8` 仍對最後一個字開窗）。
- **無效候選過濾（2026-07-27）**：候選值與其跨距目前顯示的文字相同者（選了也不會變）一律隱藏——「聽不懂」錨在懂上時不再列出 聽不懂/不懂/懂 自己；過濾後若一個候選都不剩，選單不開啟。
- 翻頁：`8` 下一頁、`7` 上一頁；**不環繞**（邊界按了無作用）。
- **其他任何按鍵＝關窗並執行該鍵原本功能**：`9`/`0` 關窗並移動游標、字母關窗並在游標處輸入、Backspace 關窗並刪字、Enter 關窗並 commit、Esc 關窗並清空。
- 候選窗 UI：白底圓角卡片、細邊框、選中列淡藍強調、灰色數字標籤、右下角頁碼（如 `2/4`）。
- **候選窗依螢幕縮放比例放大（2026-08-02 修正）**：候選窗是自繪 GDI 視窗，所有尺寸（字級 10pt、列高 34、頁碼列 20、邊框 1）以 96 dpi 為基準，實際依 `GetDpiForWindow` 取得所在螢幕的 DPI 換算，字型也依該 DPI 重建（跨螢幕拖曳走 `WM_DPICHANGED` 重算）。原本吃 `Global::defaultlFontHandle`（開機時以行程系統 DPI 建一次）——per-monitor aware 的宿主（LINE、Chrome）回報 96，在 150%／175% 螢幕上就會變得特別小。
- 候選窗**開在游標錨點字的正下方**（比照微軟注音；layout 追蹤錨點那一個字的子範圍，非整段組字起點）；**下方放不下（貼近螢幕/工作區底部）時自動翻到錨點字上方**，左右超界時貼邊。

### 閒置編輯層（2026-07-28 新增，2026-08-14 擴成整排數字）

無組字（idle）時，**上排數字鍵整排**被吃掉並代送對應的編輯鍵（Windows 走 SendInput、macOS 走 CGEventPost）：

| 按鍵 | 代送 | macOS |
|---|---|---|
| `1` | Home（行首） | Cmd+← |
| `2` | Shift+Home（選取到行首） | Shift+Cmd+← |
| `3` | Shift+End（選取到行尾） | Shift+Cmd+→ |
| `4` | End（行尾） | Cmd+→ |
| `5` | Delete（往右刪） | ⌦ |
| `6` | Backspace（往左刪） | ⌫ |
| `7` | ↑ | ↑ |
| `8` | ↓ | ↓ |
| `9` | ← | ← |
| `0` | → | → |

- **只攔沒有按 Shift 的數字**。Shift+數字照舊走標點路徑（`!`→！、`(`→（、`)`→）、`^`→……），與小狼毫一致。
- **中文與英文模式共用同一層（2026-08-14）**：閒置＝編輯層、有組字串＝各自的原本行為，習慣不必隨模式切換。英文模式下組字串非空時數字是**字面數字**，所以 `user123` 一路打得完。
- **按住 Ctrl 或 Alt 一律不接手**（2026-08-14）：否則 Ctrl+1 會變成 Home、Ctrl+A 會被吞掉。這個前置判斷在改成「一律吃掉剩下的可見字元」之後是必要的——先前是靠「沒對映就放行」意外擋住的。
- **NumPad 不受影響**：數字鍵盤照常打出數字（見〈九宮格豁免〉）。筆電若沒有內嵌數字鍵盤，中文模式下打數字要 Shift 切英文；Fn 鍵由鍵盤韌體處理，作業系統看不到，無法拿來當修飾鍵。
- `1`-`4` 由中間往外讀：左邊兩個往左、右邊兩個往右，各自靠內的那個是「選取」。
- 2／3 注入時會自己包一組 Shift。這不會誤觸「Shift 單獨輕按＝中英切換」：中間那個 Home/End 會走到 `Global::UpdateModifiers` 的 default 分支清掉 `IsShiftKeyDownOnly`，`CheckShiftKeyOnly` 就不會放行 preserved key。
- 注入鍵會再繞回輸入法一次，但閒置時方向鍵／刪除鍵一律放行，所以是 no-op。

**2026-08-14 取消的三個鍵**：`-`、`=`、`Tab`。

- `-`/`=` 原本是閒置 Home/End、組字中跳頭尾，現在**不再做導航**，那份工作由 `1`/`2` 接手。（2026-08-14 到 08-16 之間它們連字都不打；**2026-08-16 起改為打出半形 `-`/`=`**，見〈標點符號〉。）
- `Tab` 原本＝Backspace，現在**完全還給應用程式**（切換欄位／自動完成／縮排都回來了），工作由 `6` 接手。順帶解決 macOS 上唯一修不好的缺陷：Chromium 系宿主（Slack／VS Code／Chrome）即使輸入法回傳 YES 仍會自行移動焦點，詳見 `mac/docs/NOTES.md`。
- 決策記錄（2026-07-28 拍板、2026-08-14 推翻）：`-`/`=` 曾經不分 Shift 一律攔下。現在改為完全不攔，Shift+`-`＝「——」因此在閒置時也回來了（會開一段新的組字串，與 Shift+`1`＝「！」同一個行為）。
- 決策記錄（2026-07-28 撤銷）：曾實作「閒置按 `8` 對既有文字反查選字（重選字）」，實測大多數應用程式不支援在已上屏文字上讀取／開 composition（僅文字編輯器可用），整組功能已移除。

### 注音符號輸入（2026-08-17 改版：兩條路，`` ` `` 功能鍵已移除）
- **`` ` `` 不再是功能鍵（2026-08-17）**：整組「反引號定案／挖空聲母」機制刪除
  （`hollowFinal_`、`feedHollowFinal`、`HollowFinalDisplay` 一併移除），這顆鍵回歸半形 `` ` ``，
  與 `-` `=` `+` 同一類（Rime `half_shape` 也是原樣送出）。Shift 位的 `~` 維持全形 ～ 不變。
- 剩下兩條路，都不需要特殊鍵：
  1. **空白鍵**：音節查無無聲調讀音時（`nc`＝ㄋㄧㄠ、`f`＝ㄈㄛ），空白鍵沒有字可以定案，
     就把**注音本身**定案成固定符號融入組字串。
  2. **Enter**：畫面上還是注音的部分一律原樣送出（見上面的 Enter 條）。`k`→ㄎ、`n`→ㄋ。
- 定案的注音是詞格中的單一候選 literal 節點（\x01＋符號 讀音）：可與中文混排、游標編輯、
  Backspace 逐符號刪，與整段一起上屏。
- **代價（使用者已知並接受）**：單獨的韻母（ㄠ、ㄧㄝ）打不出來了——原本要靠 `` `k ``／`` `x ``。
  純韻母的需求罕見，不值得為它留一顆功能鍵。
- 對定案注音開選單只有它自己一個候選→經「無效候選過濾」後選單不開啟。

### 中英切換（Shift 輕按，2026-08-08 v5 定案：不 commit，英文長在組字串裡）
- **單獨輕按 Shift**（按下到放開之間無其他鍵）＝中/英模式切換；Shift+字母照常輸出大寫、不觸發切換。實作走 TSF **preserved key**（樣本原本的 IME-mode 保留鍵接管改造）——TSF 會在 KeyEventSink 之前攔截，不能用按鍵事件偵測。
- 英文模式＝**系統鍵盤關閉狀態**（GUID_COMPARTMENT_KEYBOARD_OPENCLOSE）：工具列中/英指示跟著變（與微軟注音一致）。
- **切換不再上屏（2026-08-08 v5，取代 v2 的 commit 式）**：
  - **有未 commit 的組字串時**：整段留著、虛線底線照舊，只把進行中的音節定案。切到英文後打的字**直接加進同一個組字串**（以 literal 讀音進詞格，與標點／定案注音同一機制），再按 Shift 切回中文可以繼續接中文。整串只在 **Enter／失焦／NumPad** 才上屏。
  - **沒有組字串時**：純粹切模式，按鍵全數放行給應用程式（英文為一般無底線編輯，行為與過去相同）。
  - 實作：鍵盤關閉時 `_IsKeyEaten` 仍會問一次 `IsVirtualKeyNeedMspyEnglish`。composer 非 kEmpty 時吃可見 ASCII，走 `FUNCTION_ENGLISH_INPUT` → `Composer::feedEnglishChar`（保留大小寫）；Backspace 刪字、Enter 上屏、Esc 清空、方向鍵吃掉。composer 為 kEmpty 時**只吃沒按 Shift 的數字排**（閒置編輯層，2026-08-14），其餘全放行。Tab、Ctrl/Alt 組合與功能鍵一律放行。
  - 英文模式下**空白鍵＝字面空白**（才打得出多字片語）；要上屏按 Enter。
- **分隔空白規則（2026-08-08 v5：只在組字串內部，兩邊都是自己的字）**：
  - 切**英文**時：游標左邊是**中文字或注音符號** → 補一個半形空白。
  - 切**中文**時：游標左邊是**英文字母或數字** → 補一個半形空白。
  - 其他情況（標點、已經有空白、組字串空的）不補。判斷對象是 composer 自己的組字串，**不讀應用程式文件、不猜**，因此 100% 準確。
  - **沒有組字串時一律不補**（2026-08-08 拍板）：已上屏的中文後面切英文、或閒置打完英文切回中文，空白由使用者自己按。
  - 決策記錄：v3「讀游標左邊字元」只有完整 TSF app 讀得到；v4 改用被動記憶（自己 commit 的尾字＋目擊放行的按鍵＋滑鼠 hook／游標快照歸零），準確度仍受宿主限制。v5 把英文收進組字串後，需要補空白的場合兩側都在自己手上，**v4 那整套被動記憶（`_lastCharClass`、commit 游標快照、執行緒 WH_MOUSE hook）已全部刪除**。
- **中英模式各應用程式獨立記憶（2026-08-02 新增，比照微軟注音／Rime）**：
  - 每個**應用程式（行程）**記自己的中/英；剛啟動的應用程式一律**英文**（`InitializeSampleIMECompartment` 設 FALSE）。
  - 焦點回到某應用程式時（`ITfThreadMgrEventSink::OnSetFocus` 拿到非空 doc mgr、`ITfKeyEventSink::OnSetFocus(TRUE)`）把記憶中的模式寫回 compartment——TIP 本來就跑在該應用程式的行程內，這份記憶天然是 per-app；重寫是為了蓋掉系統跨應用程式同步的開關狀態。
  - 記憶只由**自己看得到的切換**更新（Shift 輕按）。工具列點擊 中/英 圖示切換無法與系統同步寫入區分，故不納入記憶（切換到別的 app 再回來會回到記憶值）。

## 7. 學習（2026-08-09 重做：上下文硬性覆寫）

### 一句話

**「在〈上下文〉後面，讀音〈X〉要打成〈值〉。」** 命中就對詞格下**高分節點覆寫**
（`overrideCandidate` 的 `kOverrideValueWithHighScore`），不是加分數——所以**改一次就一定生效**。

### 記錄格式

檔案：`%APPDATA%\MspyIME\user-choices.txt`

```
值 讀音鍵 上下文 次數 序號
杯 ㄅㄟ 鋼 2 17
杯 ㄅㄟ 鏽鋼 1 18
一 ㄧ ^ 1 4
```

- **上下文＝該跨距前面的一個字與兩個字**，每次選字**兩種長度都寫**；查詢時長的優先。
  這樣「鋼→杯」在完全沒提到「鏽」的句子裡照樣命中，而「鏽鋼→杯」在兩者都命中時勝出。
- 上下文取的是**字**，不管那個字屬於多長的詞——「不鏽鋼」裡的「鋼」照樣是合法上下文。
- `^` 代表前面沒有可用的字：組字串開頭，或標點／已定案注音／英文之後（那些是 literal 讀音，
  跨過去的上下文毫無意義）。
- **沒有時間衰減**。強弱只看「使用者最後做了什麼」，不看多久以前做的。
- 序號讓兩個應用程式各自的 TIP 實例在合併存檔時得到相同結果（每個 app 各有一份實例）。

### 更新規則

`record(上下文, 讀音, 值)`：

1. 被選中的值一律排到該 (上下文, 讀音) 的**第一名**（次數取 `max(自己+1, 最強對手+1)`，上限
   `kMaxCount`＝8）。這就是「改一次就夠」的實作——不需要贏過對手累積的次數。
2. 每個對手**次數 −1**，歸零即刪除。所以改回去一樣便宜，不會被自己的舊習慣鎖住。

### 套用規則

- 時機：每次 `insertReading`／`insertLiteralText`／Backspace 重走詞格之後（`applyLearnedOverrides`）。
- 掃描每個位置、每個長度（上限 4 音節），長的優先；命中就覆寫、重走，再從頭掃一次，直到沒有變化。
- **已經被覆寫的節點一律跳過**：那是使用者自己選的字、保護它的釘子，或前一輪已套用的修正。
  所以自動修正永遠不會跟使用者當下的選擇吵架。
- 每次自動覆寫都跟手動選字一樣**只動自己的跨距**（同樣走 §6 的釘回機制）。

### 決策記錄（2026-08-09）：前一套為什麼換掉

使用者回報「改了兩次以上還是記不住」。以 REPL 實測「不鏽鋼杯」（`bu2xq4gh1bz1` → 不鏽鋼**悲**）
確認是兩個獨立的失效：

1. **選單第 1 個候選「鋼杯」（兩字）學到了，但沒有用。**
   舊機制把偏好加在「該讀音鍵最佳分數 +1e-6」上，而整條路徑 `不鏽鋼(-5)+悲(-3)` 本來就贏過
   `不(-2)+鏽(-3)+鋼杯(-6.8)`，1e-6 翻不過來。實測：塞一份 `鋼杯 ㄍㄤ-ㄅㄟ 8 <剛剛>` 的偏好檔
   再打一次，輸出仍是「不鏽鋼悲」。把 margin 加大就會扭曲跨距競爭（丼／動作問題），不是解法。
2. **選單第 2 個候選「杯」（單字）什麼都沒學到。**
   舊規則是「單字選擇改學上下文兩音節詞，且只與**單字節點**配對」，而左鄰是三字詞「不鏽鋼」，
   配不出來就整個放棄。

新機制對兩者都成立：單字選擇記 `(鋼, ㄅㄟ) → 杯`，套用時是硬覆寫，不必跟路徑分數競爭。

### 決策記錄（2026-08-04，已被上面取代）：更早的那一套為什麼換掉

- 最早是把 `值 讀音鍵` 餵給 McBopomofo 的 `UserPhrasesLM`，而該類別給**每一筆使用者詞的分數都是 0**。
  字典分數是負的對數機率，所以任何一筆使用者詞都輾壓字典；詞格 walk 用嚴格 `>` 比較、
  候選用 `stable_sort`、字典按行序載入——**同一個讀音鍵下最早寫進檔案的那一筆永遠贏**。
  後果是改不掉、一次性情境選擇綁架整個讀音、學習檔讓輸出比不學習還差
  （實測 `wo3vidk4` 純字典出「我知道」，載入學習檔反而出「我之道」）。
- 2026-08-04 的加權版修好了「改不掉」，但如上所述沒修好「贏不了整句路徑」。

### 遷移

舊的 `user-phrases.txt` **沒有上下文欄位**，無法轉成新記錄。載入時直接改名為
`user-phrases.txt.bak` 留在原地（不刪），新檔從空的開始學。
`UserOverrideModel`（工作階段內的 LRU＋時間衰減）與 `UserPreferenceLM`（加分層）**整組移除**，
學習只剩這一套。
